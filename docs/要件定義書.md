# タスク管理アプリ 要件定義書

更新日: 2026-10-04 · 作成: @神崎

## 1. 概要

ブラウザだけで動く、Trello 風のタスク管理アプリを作る。タスクをカードとしてリストに並べ、ドラッグで動かして進み具合を管理できる。

| 項目 | 内容 |
| --- | --- |
| アプリ名 | タスク管理アプリ（仮） |
| 目的 | 講義課題の提出物。HTML / CSS / JavaScript と git / GitHub の使い方を学ぶ |
| 想定利用者 | 作成者本人 1 人 |
| 利用場面 | 自分のやることを「やること → 作業中 → 完了」の流れで管理する |
| 公開先 | GitHub Pages（URL を開くだけで使える） |

## 2. 用語

アプリは「ボード > リスト > カード」の 3 層でできている。

| 用語 | 意味 | 例 |
| --- | --- | --- |
| ボード | 画面全体。1 つだけ持つ | 「私のタスク」 |
| リスト | カードを縦に並べる列。横に並ぶ | 「やること」「作業中」「完了」 |
| カード | 1 つのタスク | 「レポートを書く」 |

## 3. 機能要件

必須は F-01〜F-05 の 5 つ。任意の機能は、必須がすべて終わって時間があれば取り組む。

| ID | 機能 | 詳しい内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | リストの管理 | リストを追加・名前変更・削除できる。初期状態は「やること」「作業中」「完了」の 3 つ | 必須 |
| F-02 | カードの管理 | 各リストにカードを追加・編集・削除できる。空のタイトルは追加できない | 必須 |
| F-03 | ドラッグ＆ドロップ | カードをマウスでつかみ、別のリストや同じリストの別の位置へ移動できる | 必須 |
| F-04 | データの保存 | 変更するたびに自動で保存し、ブラウザを閉じても次に開いたときに元に戻る | 必須 |
| F-05 | Web 公開 | GitHub Pages で公開し、URL を開くだけで使える | 必須 |
| F-06 | 削除の確認 | リストを削除する前に「本当に削除しますか？」と確認する | 任意 |
| F-07 | リストの並べ替え | リスト自体をドラッグで左右に並べ替える | 任意 |
| F-08 | 期限・優先順位 | カードに期限日と優先順位（高・中・低）を付けられる。優先順位はカード上のラジオボタンで切り替える。期限が 2 日以内なら黄色、過ぎたら赤で表示する | 任意 |
| F-09 | 期限順の並べ替え | 「期限順に並べる」ボタンで、各リストのカードを期限が近い順に並べる。期限なしは最後、同じ期限なら優先順位の高い順 | 任意 |

## 4. 非機能要件

機能とは別に、動作環境や使いやすさの条件を次のように決める。

| ID | 項目 | 条件 |
| --- | --- | --- |
| N-01 | 対応ブラウザ | Google Chrome / Microsoft Edge の最新版で動く |
| N-02 | 外部ライブラリ | 使わない。HTML / CSS / JavaScript だけで作る |
| N-03 | インストール | 不要。ブラウザで開くだけで使える |
| N-04 | 画面サイズ | パソコン画面を主に想定。スマホでは横スクロールで全リストを見られる |
| N-05 | データの保存先 | ブラウザ内（localStorage）。端末ごと・ブラウザごとに別のデータになる |
| N-06 | 操作の応答 | 追加・移動・削除の結果がすぐ画面に反映される |
| N-07 | ソース管理 | git で管理し、機能ごとにコミットして GitHub に上げる |

## 5. 画面イメージ

画面は、横に並んだリストとその中のカードでできている。各リストの下でカードを追加し、右端でリストを追加する。

（画面イメージの図は [Claude Docs 版の要件定義書](https://claude.ai/artifact/HKyKeqHcS2dZFcdWxkVmcc) を参照）

画面の動きは [タスク管理アプリ モック](https://claude.ai/artifact/DM9cqF4s2z7btjN1AdMn6a) で試せる。同じファイルをリポジトリの `mock/kanban-mock.html` にも置いている。

## 6. データ構造

ボード全体を 1 つの JSON にまとめ、localStorage のキー `trello-board` に保存する。配列の順番がそのまま画面の並び順になる。

```json
{
  "lists": [
    {
      "id": "list-1",
      "title": "やること",
      "cards": [
        { "id": "card-1", "title": "レポートを書く", "priority": "high", "due": "2026-10-10" },
        { "id": "card-2", "title": "資料を読む", "priority": "mid", "due": null }
      ]
    },
    { "id": "list-2", "title": "作業中", "cards": [] },
    { "id": "list-3", "title": "完了", "cards": [] }
  ]
}
```

| 項目 | 型 | 説明 |
| --- | --- | --- |
| id | 文字列 | リスト・カードを区別する重複しない番号 |
| title | 文字列 | 画面に表示する名前 |
| cards | 配列 | そのリストに入っているカード。上から順に並ぶ |
| priority | 文字列 | カードの優先順位。high（高）・mid（中）・low（低）のどれか。ない場合は mid として扱う |
| due | 文字列 または null | カードの期限日（YYYY-MM-DD）。期限がないときは null |

## 7. 技術構成

アプリ本体のファイルは 3 つ（＋説明用の README）で、作業フォルダ `C:\Users\kanza\kadai` に置く。

| ファイル | 役割 |
| --- | --- |
| index.html | 画面の骨組み |
| style.css | 見た目（横並びのリスト、カードの影など） |
| app.js | 動き（追加・削除・ドラッグ・保存） |
| README.md | アプリの説明と使い方 |

| 用途 | 使うもの |
| --- | --- |
| エディタ | Cursor |
| ドラッグ＆ドロップ | ブラウザ標準の HTML Drag and Drop API |
| 保存 | ブラウザ標準の localStorage |
| バージョン管理 | git（ブランチ `main`） |
| 公開 | GitHub（gh コマンド）+ GitHub Pages |

## 8. 対象外（今回は作らないもの）

サーバーを使わずに作るため、次の機能は作らない。

- ログイン・ユーザー登録
- 複数人でのボード共有、同時編集
- 複数のボードの切り替え
- 別の端末・別のブラウザとのデータ同期
- カードへの画像やファイルの添付
- 通知（メールや期限のお知らせ）

## 9. スケジュール

6 つのステップを順に進め、各ステップの最後にブラウザで動作を確認してコミットする。各ステップの日付は、提出期限が決まったら入れる。

- [ ] ステップ 1：画面の骨組み（3 列のリストを表示）
- [ ] ステップ 2：カードの追加・編集・削除（F-02）
- [ ] ステップ 3：リストの追加・名前変更・削除（F-01）
- [ ] ステップ 4：ドラッグ＆ドロップ（F-03）
- [ ] ステップ 5：データの保存（F-04）
- [ ] ステップ 6：GitHub に上げて GitHub Pages で公開（F-05）
