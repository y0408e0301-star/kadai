# タスク管理アプリ 要件定義書

更新日: 2026-10-07 · 作成: @神崎

## 1. 概要

React の画面、Spring Boot の API、PostgreSQL のデータベースで動く、Trello 風のタスク管理アプリを作る。タスクをカードとしてリストに並べ、ドラッグで動かして進み具合を管理できる。

| 項目 | 内容 |
| --- | --- |
| アプリ名 | タスク管理アプリ（仮） |
| 目的 | 講義課題の提出物。Java / Spring Boot / React / PostgreSQL を使った Web アプリ開発と、git / GitHub の使い方を学ぶ |
| 想定利用者 | 作成者本人 1 人 |
| 利用場面 | 自分のやることを「やること → 作業中 → 完了」の流れで管理する |
| 公開先 | 未定（10. 未決事項）。決まるまでは自分のパソコン上で動かす |

## 2. 用語

アプリは「ボード > リスト > カード」の 3 層でできている。

| 用語 | 意味 | 例 |
| --- | --- | --- |
| ボード | 画面全体。1 つだけ持つ | 「私のタスク」 |
| リスト | カードを縦に並べる列。横に並ぶ | 「やること」「作業中」「完了」 |
| カード | 1 つのタスク | 「レポートを書く」 |

## 3. 機能要件

必須は F-01〜F-05 の 5 つ。任意の機能は、必須がすべて終わって時間があれば取り組む。

| ID | 機能 | 詳しい内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | リストの管理 | リストを追加・名前変更・削除できる。初期状態は「やること」「作業中」「完了」の 3 つ | 必須 |
| F-02 | カードの管理 | 各リストにカードを追加・編集・削除できる。空のタイトルは追加できない | 必須 |
| F-03 | ドラッグ＆ドロップ | カードをマウスでつかみ、別のリストや同じリストの別の位置へ移動できる | 必須 |
| F-04 | データの保存 | 変更するたびに API 経由で PostgreSQL に保存し、ブラウザを閉じても次に開いたときに元に戻る | 必須 |
| F-05 | Web 公開 | インターネット上に公開し、URL を開くだけで使える（公開先は 10. 未決事項） | 必須 |
| F-06 | 削除の確認 | リスト・カードを削除する前に「本当に削除しますか？」と確認する | 任意 |
| F-07 | リストの並べ替え | リスト自体をドラッグで左右に並べ替える | 任意 |
| F-08 | 期限・優先順位 | カードに期限日と優先順位（高・中・低）を付けられる。優先順位はカード上のラジオボタンで切り替える。期限が 2 日以内なら黄色、過ぎたら赤で表示する | 任意 |
| F-09 | 期限順の並べ替え | 「期限順に並べる」ボタンで、各リストのカードを期限が近い順に並べる。期限なしは最後、同じ期限なら優先順位の高い順 | 任意 |
| F-10 | カードの検索 | タイトルの一部・リスト・優先順位・期限の範囲でカードを絞り込み、条件に合うカードだけをボードに表示する。条件はどれも省略できる。「クリア」で全カードの表示に戻る | 任意 |

## 4. 非機能要件

機能とは別に、動作環境や使いやすさの条件を次のように決める。

| ID | 項目 | 条件 |
| --- | --- | --- |
| N-01 | 対応ブラウザ | Google Chrome / Microsoft Edge の最新版で動く |
| N-02 | 技術スタック | バックエンドは Java + Spring Boot、フロントエンドは React、データベースは PostgreSQL。Next.js は使わない。詳しくは 7. 技術構成 |
| N-03 | インストール | 利用者は不要で、ブラウザで開くだけで使える。開発用のパソコンには JDK・Node.js・Docker を入れる |
| N-04 | 画面サイズ | パソコン画面を主に想定。スマホでは横スクロールで全リストを見られる |
| N-05 | データの保存先 | サーバー側の PostgreSQL。どの端末・ブラウザから開いても同じデータになる |
| N-06 | 操作の応答 | 追加・移動・削除の結果がすぐ画面に反映される |
| N-07 | ソース管理 | git で管理し、機能ごとにコミットして GitHub に上げる。バックエンドとフロントエンドは同じリポジトリに置く |
| N-08 | 通信の形式 | 画面とサーバーは REST API（JSON）でやり取りする |

## 5. 画面イメージ

画面は、横に並んだリストとその中のカードでできている。各リストの下でカードを追加し、右端でリストを追加する。

（画面イメージの図は [Claude Docs 版の要件定義書](https://claude.ai/artifact/HKyKeqHcS2dZFcdWxkVmcc) を参照）

## 6. データ構造

データは PostgreSQL の 2 つのテーブル `lists` と `cards` に保存する。並び順は `position` 列で持ち、小さい順に画面へ並べる。テーブルは Flyway のマイグレーション（SQL ファイル）で作る。

```sql
CREATE TABLE lists (
  id         BIGSERIAL    PRIMARY KEY,
  title      VARCHAR(100) NOT NULL,
  position   INTEGER      NOT NULL,
  created_at TIMESTAMP    NOT NULL DEFAULT now(),
  updated_at TIMESTAMP    NOT NULL DEFAULT now()
);

CREATE TABLE cards (
  id         BIGSERIAL    PRIMARY KEY,
  list_id    BIGINT       NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
  title      VARCHAR(200) NOT NULL,
  position   INTEGER      NOT NULL,
  priority   VARCHAR(4)   NOT NULL DEFAULT 'mid'
             CHECK (priority IN ('high', 'mid', 'low')),
  due        DATE,
  created_at TIMESTAMP    NOT NULL DEFAULT now(),
  updated_at TIMESTAMP    NOT NULL DEFAULT now()
);
```

| 列 | テーブル | 型 | 説明 |
| --- | --- | --- | --- |
| id | lists / cards | 整数（自動採番） | リスト・カードを区別する重複しない番号 |
| title | lists / cards | 文字列 | 画面に表示する名前。空は不可 |
| position | lists / cards | 整数 | 並び順。リストは左から、カードは上から小さい順 |
| list_id | cards | 整数 | カードが入っているリストの id。リストを消すと中のカードも消える |
| priority | cards | 文字列 | 優先順位。high（高）・mid（中）・low（低）のどれか。初期値は mid |
| due | cards | 日付 または null | 期限日。期限がないときは null |
| created_at / updated_at | lists / cards | 日時 | 作成・更新した日時 |

画面が最初に読む `GET /api/board` は、ボード全体を次の形の JSON で返す。配列は position 順に並んでいる。

```json
{
  "lists": [
    {
      "id": 1,
      "title": "やること",
      "cards": [
        { "id": 1, "title": "レポートを書く", "priority": "high", "due": "2026-10-10" },
        { "id": 2, "title": "資料を読む", "priority": "mid", "due": null }
      ]
    },
    { "id": 2, "title": "作業中", "cards": [] },
    { "id": 3, "title": "完了", "cards": [] }
  ]
}
```

## 7. 技術構成

バックエンドは Java + Spring Boot、フロントエンドは React、データベースは PostgreSQL で作り、そのほかのツールはこの 3 つに合わせて選んだ。Next.js は使わない。ファイルは作業フォルダ `C:\Users\kanza\kadai` に次のように置く。

| フォルダ・ファイル | 役割 |
| --- | --- |
| backend/ | API サーバー（Java + Spring Boot） |
| frontend/ | 画面（React） |
| compose.yaml | 開発用の PostgreSQL を Docker で起動する設定 |
| mock/ | 画面の動きを試すモック |
| docs/ | 要件定義書 |
| README.md | アプリの説明、起動方法、使い方 |

| 区分 | 用途 | 使うもの |
| --- | --- | --- |
| バックエンド | 言語 | Java 21（LTS） |
| バックエンド | フレームワーク | Spring Boot（Spring Initializr で選べる最新の安定版）+ Spring Web |
| バックエンド | DB アクセス | Spring Data JPA |
| バックエンド | テーブルの作成・変更 | Flyway |
| バックエンド | 入力チェック | Bean Validation（空のタイトルを拒否） |
| バックエンド | ビルド | Maven |
| バックエンド | テスト | JUnit 5 + Spring Boot Test |
| バックエンド | コードチェック | spring-javaformat（Spring Boot 本体と同じ書式か）+ SpotBugs（バグになりやすい書き方）。`mvnw verify` で実行 |
| フロントエンド | 言語 | TypeScript |
| フロントエンド | ライブラリ | React |
| フロントエンド | 開発サーバー・ビルド | Vite |
| フロントエンド | ドラッグ＆ドロップ | dnd-kit |
| フロントエンド | API の呼び出し | ブラウザ標準の fetch |
| フロントエンド | パッケージ管理 | npm |
| フロントエンド | コードチェック | oxlint（Vite の React テンプレートに入っているもの）。React Hooks・アクセシビリティ・import のチェックを足し、警告もエラー扱いにする |
| フロントエンド | ユニットテスト | Vitest（期限の表示など、計算の部分） |
| フロントエンド | E2E テスト | Playwright（画面を操作し、DB の中身と再読み込み後の表示を確かめる。ブラウザはパソコンの Edge） |
| データベース | DB | PostgreSQL 17 |
| データベース | 開発環境での起動 | Docker Compose |
| 共通 | エディタ | Cursor |
| 共通 | バージョン管理 | git（ブランチ `main`） |
| 共通 | リポジトリ | GitHub（gh コマンド） |
| 共通 | 自動チェック | GitHub Actions（PR と main への push ごとに、両方のコードチェック・ビルド・API のテストを実行） |

開発中は Vite の開発サーバー（`http://localhost:5173`）で画面を開き、`/api` へのリクエストを Spring Boot（`http://localhost:8080`）へ転送する。API は次の 12 個。

| メソッド | パス | 内容 | 機能 |
| --- | --- | --- | --- |
| GET | /api/board | 全リストとカードをまとめて取得 | F-04 |
| GET | /api/cards | カードを検索（タイトルの一部・リスト・優先順位・期限で絞り込む。条件はどれも省略できる） | F-10 |
| GET | /api/cards/{id} | カード 1 枚を取得（入っているリストの id と名前も返す） | F-04 |
| POST | /api/lists | リストを追加 | F-01 |
| PATCH | /api/lists/{id} | リスト名を変更 | F-01 |
| DELETE | /api/lists/{id} | リストを削除（中のカードも消える） | F-01 |
| POST | /api/lists/{listId}/cards | カードを追加 | F-02 |
| PATCH | /api/cards/{id} | カードのタイトル・期限・優先順位を変更 | F-02, F-08 |
| DELETE | /api/cards/{id} | カードを削除 | F-02 |
| PUT | /api/cards/{id}/move | カードを別のリスト・位置へ移動（移動先の listId と position を送る） | F-03 |
| POST | /api/board/sort-by-due | 各リストのカードを期限順に並べ替えて保存し、並べ替えたあとのボードを返す | F-09 |
| GET | /api/health | サーバーが動いているかの確認（`{"status":"ok"}` を返す） | ― |
